# 24 · 插件诊断：命令可用性与错误记录

[索引](README.md) · 相关：[18 激活与代理资源](18-ACTIVATION-AND-BROKER.md) · [21 面板开发](21-PANEL-UI-GUIDE.md)

插件出问题时，用户需要知道“为什么”。这套机制的原则是：**Core 观测为主，插件上报为辅**。

## 1. 为什么以 Core 观测为主

插件崩溃、握手超时、进程退出时，插件端根本没有机会发消息。Core 能看见的失败才是完整且不可伪造的：

| source       | 谁产生    | 覆盖的失败                                  |
| ------------ | --------- | ------------------------------------------- |
| `plugin`     | Core 观测 | RPC 返回错误、超时、进程退出/崩溃           |
| `panel`      | Core 观测 | 面板 HTML/资源加载失败                      |
| `bridge`     | Core 观测 | 握手超时、方法不在白名单、端口关闭          |
| `permission` | Core 观测 | 激活失败、授权不完整                        |
| `command`    | Core 观测 | 插件申请的命令在本地 PATH 中不存在（见 §2） |
| `ui`         | 插件上报  | 面板内未捕获异常（Core 看不到的那部分）     |

激活前的正常拒绝（未安装、未授权、插件未启用）不会入日志，避免噪音。

## 2. 外部命令可用性

- Core 在 `plugins_list` 里为每个插件返回 `missingCommands`：已申请但 `which` 解析不到的命令。
- 权限请求对话框会在允许该命令前显示红色警告：“本地未找到该命令，允许后插件也可能无法工作。”
- 插件详情的命令列表里，缺失项标记为红色；外部命令配置弹窗同样标记。
- 检查发生在读取插件列表时，因此装完命令后刷新设置页即可恢复正常。

## 3. 错误记录

- 每个插件最多保留 **50 条**，新的在前；`message` 截断到 500 字符，`detail` 到 4000 字符。
- 纯内存：重启后清空，不写入插件目录，也不上传。
- 存储层拒绝空消息；未知 `source` 归并为 `ui`，避免插件伪造任意标签。

RPC 错误由 Core 自动记录，插件作者不需要额外调用；把有意义的说明写进错误的 `message`/`detail` 即可。

### 3.1 Rust 插件如何上报

同步失败继续返回 `Err(RpcError)`，Core 自动记录。只有 **RPC 返回之后** 才发生的失败（后台任务、事件推送、部分成功）才需要显式上报：

```rust
host.report_error(
    "gpg.no_secret_key",
    "没有匹配的私钥",
    Some("fingerprint 0123… 不在 keyring"),
)?;
```

- `code` 必填，`[a-z0-9._-]`、≤64 字符，用于设置页分类；
- `message` ≤500 字符，`detail` 可选、≤4000 字符；
- 每个插件 **10 条/分钟**，超出静默丢弃，不会让插件失败；
- 记录来源是 `plugin`，和 RPC 错误同一个环形缓冲。

### 3.2 面板 UI 主动上报

只有 Core 观测不到的场景才需要上报，例如面板渲染崩溃：

```ts
await client.errors.report('无法渲染文档', error.stack)
```

SDK 还会自动捕获 `window.onerror` 与 `unhandledrejection`，限流 **1 条/秒、每次会话 5 条**，避免坏掉的渲染循环刷屏。

## 4. 在哪里查看

**设置 → 插件 → 插件详情 → 最近错误**：按来源标记（`plugin`/`panel`/`bridge`/`permission` 显示为红色），列出时间、消息与可选的详情，并提供“清空记录”。

没有记录时显示提示，说明哪些失败会被记录，便于用户判断是插件问题还是环境问题（例如命令未安装）。

## 5. 测试

- Rust：错误存储的上限、顺序、截断、来源归并、空消息拒绝；`missingCommands` 只报告 PATH 解析不到的名字。
- e2e：缺失命令在权限请求与详情页显示为红色；错误列表可读取与清空。
