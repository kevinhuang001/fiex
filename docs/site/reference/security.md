# 插件权限与安全边界

## 两类机制一起工作

Fiex 的插件安全由 Core 授权检查和操作范围检查组成，并由平台进程沙箱提供额外限制。插件必须通过 Core/SDK 的受控接口访问文件、网络、存储与凭据。

- **Manifest 声明**：插件可以申请哪些能力。
- **用户批准**：安装/激活时，用户选择允许哪些已声明能力。Core 保存用户批准时的声明快照；插件后续扩大声明不会静默继承新授权。
- **Operation Scope**：本次调用允许操作哪些文件、目录、主机或命令。授权某项能力不等于允许访问任意对象。
- **平台沙箱**：Linux 使用 Landlock 和 seccomp；macOS 使用 Seatbelt；Windows 使用 AppContainer 和 Job Object。沙箱不能建立时，Core 不会把插件作为未沙箱进程继续启动。

Core 对每个宿主服务调用继续检查权限、资源归属、作用域和目标；OS 沙箱不是替代这些业务授权的唯一防线。

## 权限类型

| 能力                                          | 作用                                 |
| --------------------------------------------- | ------------------------------------ |
| metadata                                      | 读取对象属性；不代表可以读取文件内容 |
| folders.read / create / delete / rename       | 对目录进行对应操作                   |
| files.read / write / create / delete / rename | 对文件进行对应操作                   |
| network                                       | 使用经 Core 授权的网络域名/地址      |
| commands                                      | 请求运行 manifest 精确列出的外部命令 |
| hooks                                         | 声明生命周期 hook 能力               |

权限可以按能力组逐项选择。关闭某个权限不必然停用整个插件；插件调用未授权能力时会被拒绝，适用时由 Core 再询问用户。

## 网络与命令

网络域名按精确目标校验，不使用通配符授权。声明 network.all 表示允许任意主机，是比精确域名更宽的选择。连接目标、重定向和 SDK 网络请求仍由 Core 网络代理检查。

外部命令具有更高风险。被批准的命令由宿主运行时启动，并以当前用户权限执行；它可能访问 SDK 文件 scope 以外的路径、联网或启动其他程序。因此，commands 授权的风险不同于通过 Core 文件 API 读取选定文件。

## 凭据

插件凭据由系统凭据存储服务管理。不要把密码、OAuth secret 或访问令牌写入连接配置、日志或公开 issue。仓库中的示例凭据只能用于本地测试，不能复用到个人账户。
